## A. 一句话的答案就能改变行为

### A3. 急停是"阻尼"还是"滑行"？

| | |
|---|---|

## B. 数值，猜的

### B1. 编队的速度常数

```python
NOMINAL_MAX_SPEED_MPS = 3.0     # 归一化 1.0 对应多少 m/s
NOMINAL_SPEED_MPS     = 1.2     # 编队时用的速度
MAX_STEP_M            = 0.35    # 单步最大位移
```

**后果**：仿真实测一步走 **0.22 m**，六步约 **1 m**。真机上如果 3.0 这个数偏大，编队会**走过头**；偏小则**步数不够、收敛不了**。

**怎么测**：让狗走一条已知距离（地上贴胶带），量实际走了多少。**一次测量就能把 `NOMINAL_MAX_SPEED_MPS` 定下来**，然后编队的射程就能从"约 1 米"变成"约 N 米"。

### B2. 标签要多大才读得准（**已经能算出来了**）

检测器需要标签在画面里 **≥64 px** 才能信任它的 **id**（`MIN_PX_PER_CELL × CELLS_ACROSS`，36h11 的 8 格）。低于这个数它**不是失败，是开始猜 id** —— 而猜错 id 会**把一只狗的位置算到另一只身上**。

**150 mm 标签要 64 px，需要约 430 px/m。** 在 4 米场地上：

| 相机宽度 | px/m | 150mm 标签 | 结果 |
|---|---|---|---|
| 720p (1280) | 320 | 48 px | ❌ **低于阈值** |
| 1080p (1920) | 480 | 72 px | ✅ 刚够 |
| 打印成 300mm | — | 144 px @1080p | ✅ 舒服 |

**这条是模拟场地自己暴露的**：它原本把标签画成硬编码的 0.30 m（无视 `marker.size_m`），改成真实分辨率后 150mm 的标签只有 60 px —— 正好卡在阈值下面。

**真机上要确认的**：相机实际多宽、场地实际多大、打印出来的黑方块**用尺子量**是不是 150 mm。这三样决定标签读不读得准。

### B3. 相机的高度、视场角

```python
hfov_deg   # 默认 60
DEFAULT_SIZE_M = 0.15   # 标记边长
```

**后果**：影响 `readiness` 里算的"能读多远"和标定的换算。

**怎么测**：把标记放在已知距离上，看它有多少像素宽 → 反推视场角。

### B4. 场地标定的高度

标定面板要操作员填**标记离地高度**和**相机高度**。填错了，`scale_factor = H/(H-h)` 就错，**所有距离按同一个比例缩放**。

**怎么测**：报告里那条「(地面标定，距离偏大 ×1.163 —— 实际约 1.31 m)」的提示是**故意留的**：如果你按地面标定，界面会一直提醒你距离偏大。**把标定点放在标记高度上，这一项就归零。**

## E. 两台狗不是同一代

```
dog1  B42N6000Q3UC1M8C   有 AES 密钥
dog2  B42D1000P4J7JC08   dev.key 是空的  → 固件 <1.1.15，不需要密钥
```

**这是整份清单里最容易踩的坑**：按一台狗的经验配另一台，会得到"一台能连、一台握不上手"，而错误信息不会告诉你为什么。
