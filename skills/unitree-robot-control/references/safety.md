# 安全规程

**在发出任何会动机器人的调用之前读这一页。**

## 物理环境（Agent 看不到，必须问）

发出移动/动作类调用前，逐条确认：

1. **人机距离**：机器人手臂/腿的活动范围内有没有人？R1 的手臂展开可达约 1 m，
   舞蹈/武术动作幅度更大。周围至少留 2 m 净空。
2. **地面**：平整、不打滑、不是桌面/台阶/斜坡。R1 摔倒的姿态无法自主恢复时只能人工扶。
3. **上方**：有没有吊灯、架子、线缆？起身（701）与武术动作有抬手/跳跃。
4. **有人在场**：必须有一个能按下遥控器急停、或直接断电的人在场看着。
   无人看守时不要做任何移动类调用。
5. **电量**：低电量（`soc` 低于 20%）时动作类指令有触发掉电保护的风险，先充电。

任何一条不满足 → **停下来问操作者**，不要"先试一下"。

## 动作风险分级

| 级别 | 例子 | 前置 |
|---|---|---|
| 无害 | 读状态、读电量、`robot_stop` | 无 |
| 低风险 | 手臂手势、LED、音量、避障开关 | 手臂范围内无人 |
| 中风险 | `robot_move`、`robot_stand`、`robot_joystick` | 净空 + 有人在场 + 时长尽量短 |
| 高风险 | 舞蹈 / 武术 / 起身 / 躺下 / 零力矩 / 空翻 | 净空 + 有人在场 + `allow_dangerous` 打开 + 确认操作者明确同意 |

`robot_emergency_stop`（Damping）单独说明：
它**不是**"更安全的停止"，而是"让机器人放弃维持姿态"。
站立的 R1 被 Damping 会直接倒下。**只在机器人正在做危险动作、必须立刻中断时使用。**

## 推荐的"机器人在环"操作节奏

```
robot_get_posture            # 现在在哪
robot_move(duration_s=0.3)   # 只动很短一次
robot_get_posture            # 看回读（注意 frozen）
robot_snapshot               # 必要时看一眼视角
robot_stop
```

**一次只动一点点，每步看返回。** 不要写"移动 10 米然后做 3 个动作"这种复合计划。

`robot_stop` 会**抢占正在进行的运动窗口**（并返回 `aborted: true`），所以它是
"立刻停"而不是"等这次移动跑完"。如果它返回 `stop_not_delivered`，说明停止指令
**没能送达机器人**（链路已断或数据通道未打开）——此时不要假设机器人已停，
改用物理遥控器或电源开关。

## 首次上真机的特殊要求

第一次连一台新机器人时：

1. **悬挂试机**：如果条件允许，先把机器人吊起来（或放在支架上），
   让轮子/脚离地，逐个验证状态切换与手势，确认动作方向、幅度符合预期。
2. 用 `UNITREE_AGENT_SAFE_MODE=true` 先只读跑一轮，确认状态、电量、错误码都合理。
3. 再打开控制，从 `robot_stand` + `robot_move(duration_s=0.3, vx=0.1)` 开始。
4. 逐条走完 `verification-checklist.md`。

## Air 机型的额外风险

- **保修仅 6 个月**（Air 系列），摔倒造成的损坏大概率不在保修范围。
- Air 使用**专用起身 ONNX 策略**，起身动作的成功率依赖地面摩擦，光滑地面慎用。
- `dances_air.yaml` 只支持 602 / 604 / 607；`830 (Loco20Dof)` 速度固定，不要指望调速。
- 双足机器人本质不稳定：**任何"看起来没事"的舞蹈动作都可能因为地面/电量/姿态累积误差而摔倒。**

## 硬件与固件风险

- **固件 OTA 可能改协议。** 历史案例：G1 1.5.1 把 `data2` 改成 3，
  直接击穿了所有第三方客户端。**升级固件前先在隔离环境复测**，
  不要在即将演示/比赛前升级。
- 不要用本工具做**超出官方 App 能力范围**的事情（例如折腾零力矩状态下的控制）。
- 雷达、音频这类可选能力缺失时不影响主流程，不要为了"功能完整"强装。

## 出问题时

| 情况 | 第一动作 |
|---|---|
| 机器人正在做危险动作 | `robot_emergency_stop(confirm=true)`（接受它可能倒下） |
| 机器人乱走 / 不听指令 | `robot_stop`，然后物理按遥控器急停 |
| `robot_stop` 返回 `stop_not_delivered` | **停止指令没送达**：用物理遥控器或电源开关，别假设它停了 |
| 指令无响应（`timed_out`） | **先看机器人实际在干什么**，再决定重试 |
| 机器人报错 | `robot_errors` 看解码后的错误；电机过温/欠压要停机冷却/充电 |
| 软件完全失控 | 断电。这是唯一 100% 可靠的急停 |
